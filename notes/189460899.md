# 2026-08-28

Day 2 打卡：熟悉 Hermes 的基础使用

<br />

今天参考官方教程（https\://hermescn.org/docs/tutorials）学习了 Hermes Agent 的基础功能，覆盖第一阶段（01–05）与第二阶段（06–10）的核心内容，主要完成以下学习：

<br />

一、学习内容

<br />

1\. Hermes 工具集使用（08 · 工具与 Toolsets）

\- 掌握 web\_search、web\_extract 等网页工具，terminal、read\_file、write\_file 等文件与终端工具，以及 browser\_exec 浏览器自动化工具；

\- 理解五类常用能力：file / terminal / web / browser / vision，核心原则是"从任务反推工具，而不是从工具寻找用途"，用最小 toolsets 启动会话，减少误操作和数据暴露面；

\- 分清三件不同的事：工具可用、动作获批、结果合格——工具可用不代表每次调用都应批准。

<br />

2\. 可执行任务说明（06 · 可执行任务）

\- 掌握六部分任务结构：背景、目标、输入、限制、交付物、验收标准；

\- "请小心"不是有效限制，"不联网""不修改输入文件""只处理当前目录"才能改变行动；交付物也不等于验收：summary.md 是文件，"存在、完整、准确、未越界"才是验收标准。

<br />

3\. 会话与上下文管理（07 · 会话与续接）

\- Hermes 把会话保存在本地 SQLite，但模型每轮只看到当前上下文，不等于全部历史永久可见；

\- 掌握"继续旧会话 / 压缩 / 新建"的选择规则，重要决定应写入 session-handoff.md 交接文件，而不是依赖聊天记录。

<br />

4\. Skills 与 Memory 系统（09 · Memory 与 Skills）

\- 学会查看和使用现有 skills：Skills 是遇到某类任务时按需加载的知识与流程包（步骤、检查表、模板、脚本）；

\- Memory 只存"稳定、常用、短小"的信息（偏好、环境事实、长期纠正）；长日志、一次性 TODO、完整会议记录不适合进长期记忆。

<br />

5\. 排错与恢复（10 · 排错与恢复）

\- 建立固定排错顺序：停止 → 状态 → 配置 → 凭据 → 日志 → 文档（hermes status / doctor / logs）；

\- 理解 checkpoint 与 rollback：恢复不是重装，先保住现场再缩小故障层，并区分应用故障、模型故障、工具故障和任务验收失败。

<br />

二、实践操作

\- 使用 Hermes 完成网页内容提取、文件读写操作和浏览器自动化任务练习；

\- 在独立练习目录中，按六部分结构写了一份 task-brief.md，让 Hermes 读取三份文本生成 summary.md，并按"存在、完整、准确、未越界"验收，原始文件未被修改。

<br />

三、遇到的问题

\- 浏览器远程调试需要授权，部分网站有反爬虫机制；

\- 一开始混淆了"会话保存"和"模型上下文"，读完 07 课后厘清：保存解决"能不能找回"，上下文管理解决"这一轮带什么进模型"。

<br />

四、明日计划

\- 为一个真实场景写 tool-plan.md，练习只启用所需最小工具集，并深入理解 Hermes 的任务执行流程。

# 2026-08-29

Day 2 打卡：熟悉 Hermes 的基础使用

<br />

今天是共学第二天，主题是把 Hermes 从"能装上"练到"会用"。参考官方教程（https\://hermescn.org/docs/tutorials）第二阶段 07–09 课，围绕会话、工具和记忆做了系统练习。

<br />

一、学习内容

<br />

1\. 会话与上下文（07 · 会话与续接）

\- 理解了会话（保存在本地 SQLite、可随时恢复）与模型上下文（每轮实际带入的信息）是两回事：保存解决"能不能找回"，上下文管理解决"这一轮带什么进模型"；

\- 掌握了继续 / 压缩 / 新建会话的选择规则：目标和工作边界没变就续接；同一任务聊得过长、工具输出挤占上下文就压缩；目标已切换或旧会话里充满冲突指令就果断开新会话；

\- 学会用 session-handoff.md 交接文件沉淀"当前状态 + 下一步"，新会话开头直接喂给它，不再让模型从几十轮聊天里猜进度。

<br />

2\. 按任务选择最小工具集（08 · 工具与 Toolsets）

\- 五类常用能力的边界：file（读写检索本地文件）、terminal（执行命令，影响面最大）、web（搜索与提取公开网页）、browser（动态页面操作）、vision（看图）；

\- 核心原则"从任务反推工具"：为今天的三个小任务分别写了 tool-plan.md，只启用所需 toolsets（如 hermes chat --toolsets file,clarify），并体会了三件不同的事——工具可用 ≠ 动作获批 ≠ 结果合格。

<br />

3\. Memory 与 Skills 的分工（09 · Memory 与 Skills）

\- Memory 只存"稳定、常用、短小"的信息：我写入了"中文回答、先给结论"“本项目用 uv 管理环境”两条偏好；长日志、一次性 TODO、会议记录留在文件里按需读取；

\- Skills 是按需加载的任务流程包：把今天验证过的"提取网页→存为 markdown→注明来源和抓取时间"步骤整理成第一个自定义 skill。

<br />

二、实践操作

\- 用 /new 和 resume 完成一次跨会话续接：昨天的 summary.md 任务在新会话中恢复上下文，直接继续修改，不必重述背景；

\- 完成三个最小任务并逐一验收：①用 file 工具把三段笔记合并成一页纪要（限制不修改原文件）；②用 web\_search + web\_extract 抓取一篇教程要点并标注来源；③核对每个任务实际调用的工具与 tool-plan 的差值，关掉多余的 toolset。

<br />

三、遇到的问题

\- 一开始习惯性开着全部工具跑任务，结果 Agent 对"整理三个本地文本"的任务发起了 web\_search——回到 08 课的原则：能用更少工具就不给更多暴露面，收敩成 file 只读后行为立刻正常；

\- 交接文件写得太流水账，新会话仍然要翻很久；改写成"目标 / 已完成 / 下一步 / 禁区"四栏后，续接效率明显提高。

<br />

四、明日计划

\- Day 3：把模糊需求写成可执行任务说明——练习"背景、目标、输入、限制、交付物、验收标准"六部分结构；

\- 给 Hermes 配一个定时任务，每天早上自动汇总教程更新和群内精华。
