# 2026-08-27

记录下 hermes配置过程中遇到的问题

<br />

<br />

【1. hermes model list 报错】
问题：unrecognized arguments: list
修复：model 是交互选择器没有 list 子命令
验证：hermes config 看当前配置

```
 【2. gateway 启动缺 launchd plist】
 问题：plist missing，提示重新生成
 修复：不用管，Hermes 自动重建并启动
 验证：hermes gateway status 显示 supervised by launchd

 【3. 终端二维码显示不了】
 问题：qrcode/PIL 没装；ASCII 二维码看不清
 修复：放弃二维码，把授权链接复制到手机飞书打开
 教训：链接比二维码省事

 【4. PEP 668 阻止 pip 安装】
 问题：externally-managed-environment 报错
 修复：pip3 install --user --break-system-packages 包名
 注意：装完的 bin 目录可能不在 PATH

 【5. 飞书配置"看似成功实则没保存"】
 问题：setup 全流程走完，最后显示 No platforms configured
 修复：重新跑 setup
 验证：grep feishu ~/.hermes/config.yaml 要有内容
 教训：向导没报错 ≠ 成功，必须验证配置落盘

 【6. restart 超时 / 重启后 not running】
 问题：restart 15 秒没跑完，之后显示 not running
 修复：timeout 给足 60s+；not running 就再 start
 验证：status 看到新 PID

 【7. gateway 变僵尸进程】
 问题：进程僵死无法响应
 修复：kill -9 强杀 → hermes gateway run 后台重启
 验证：日志出现 feishu connected

 【8. DeepSeek 请求绕美国，延迟 1.04s】
 问题：全局代理把国内 API 也绕道了
 修复：~/.zshrc 的 no_proxy 加 api.deepseek.com、feishu.cn、baidu.com
 等
 效果：降到 0.13s，快 8 倍
 注意：no_proxy 通配符写法可能不生效，用裸域名

 【9. 飞书 keepalive 超时掉线】
 问题：偶发 ping 超时
 修复：不用管，几秒自动重连
 验证：status 显示已连接
```

# 2026-08-28

摸清了它的几个核心机制：命令、会话
、记忆、技能、网关

```
 【我的两种使用界面】
 1. CLI 终端：配置、排障、跑命令（hermes config / doctor / gateway）
 2. 飞书网关：日常对话干活，手机随时用，群聊需要 @ 才回复

 【常用命令（基础使用核心）】
 - hermes config：查看/修改配置
 - hermes model：切换模型提供商（我用 DeepSeek）
 - hermes gateway：status / start / restart / setup，管理飞书接入
 - hermes doctor：环境体检，--fix 自动修复
 - hermes skills list：查看已装技能
 - hermes cron list：定时任务管理（还没用，待探索）

 【理解最深的两个机制】

 1. 记忆（Memory）
 Hermes
 跨会话记住我的偏好和事实：比如我喜欢中文交流、手机端阅读、禁止表格输出
 ；我持有的港股标的、关注的分析师。这些不用每次重新交代，新会话自动带上
 。这也是对抗"AI 失忆"的关键——重要信息沉淀到外部，不依赖单次对话。

 2. 技能（Skills）
 完成复杂任务后把方法沉淀成技能，下次直接复用。我的技能列表里已有 13
 个本地自建技能：
 - 12
 个投资类：A股数据获取、港股财报、机构资金追踪、物理上限估值法、市场监
 控、专家观点知识库等
 - 1 个环境类：macOS 代理管理（配置代理时沉淀的排障流程）

 最典型的是"物理上限估值法"：单店模型 → 天花板门店数 → 利润天花板 → PE
 定市值，这套分析流程被固化成技能后，分析同类公司直接调用，不用每次从零
 教。

 【一个完整的日常任务流（以港股分析为例）】
 1. 飞书直接下指令
 2. 我调技能和数据源：AKShare 港股财报接口 + 腾讯行情 API 拿数据
 3. 套用估值框架分析
 4. 结论 + 数据源说明返回，用户可质疑追问

 整个链路是：对话 → 工具/数据 → 技能框架 → 结论。

 【踩坑心得】
 - 数据源不是唯一的：东财接口被墙就换腾讯 API，学会多备选
 - 工具能力决定 AI 上限：AI
 不是聊天框，能接数据、跑脚本、做定时任务才是真本事
 - 没报错 ≠ 成功：配置完必须验证产物（Day 1 的教训延续）

 【还没探索的】
 - 定时任务（cron）：投资监控可以做成每日自动简报
 - 子代理（delegation）：并行处理多个任务
 - 桌面端 / Dashboard
```
