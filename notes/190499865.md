# 2026-08-29

这节是 Hermes 自动化工作流最核心的生产级实战课，彻底把单次对话 AI 升级成**无人值守、状态可控、按需计费、可暂停、可止损、可彻底清理**的定时研究工作流。我全程基于 Hermes 0.18.2、Linux x86\_64 实操落地，所有命令、校验逻辑、状态流转、故障修复、TG 配置均可 100% 复现，没有玄学、没有模糊步骤，照着做就能跑通完整生产级闭环。整套项目的核心工程思想非常关键：**用极低开销的本地 Python 哈希预检脚本，替代大模型无脑轮询**，实现「数据源无变化、完全不调用 LLM、零扣费；仅增量更新时才触发 AI 总结」，从根源解决定时 AI 任务最致命的空跑计费问题。同时 Hermes 自研 Cron 调度器会强制每次任务开启**全新纯净独立会话**，不依赖任何聊天记忆，让每次输出结果稳定、可复现、可溯源。配合严格的目录隔离、最小工具权限策略、本地 Markdown 产物落地、TG 统一推送、分层止损机制，整套工作流彻底解决了传统自动 AI 任务空跑浪费、输出不可控、权限危险、推送丢消息、无法运维清理的所有问题。完整固定执行链路：定时调度触发 → 前置变更检测脚本判断状态 → 按需唤醒大模型 → 独立 Agent 处理数据 → 生成本地日报产物 → Cron 自动推送结果至 TG，业务、状态、推送完全解耦，是非常标准的轻量化生产架构。

**一、环境初始化｜完整可复现搭建步骤**：首先创建标准化隔离工作目录，统一管理输入、状态、输出、脚本资源，执行命令：`mkdir -p "$HOME/hermes-daily-research/inbox" "$HOME/hermes-daily-research/state" "$HOME/hermes-daily-research/out" "$HOME/.hermes/scripts"`；随后复制课程官方全套基准素材、提示词、验收工具与变更检测脚本，保证环境和官方基线一致，执行命令：`cp examples/lesson-18/inbox/*.md "$HOME/hermes-daily-research/inbox/" && cp examples/lesson-18/source-baseline.json "$HOME/hermes-daily-research/state/" && cp examples/lesson-18/task-prompt.txt "$HOME/hermes-daily-research/" && cp examples/lesson-18/verify_artifact.py "$HOME/hermes-daily-research/" && cp examples/lesson-18/change_gate.py "$HOME/.hermes/scripts/lesson18-change-gate.py"`；最后给预检脚本设置私有权限，防止权限泄露：`chmod 700 "$HOME/.hermes/scripts/lesson18-change-gate.py"`。重要实操禁忌：本地已有同名文件/目录绝不直接覆盖，必须更换工作目录，避免破坏已有工作流；官方示例无效域名仅占位，全程不会联网请求。环境部署后必须执行**基线哈希校验**，锁定文件完整性，避免后续检测异常、验收失败，完整可直接运行的校验代码：

`cd "$HOME/hermes-daily-research" && python3 - <<'PY' from pathlib import Path import hashlib, json root = Path.home() / "hermes-daily-research" actual = {p.name: hashlib.sha256(p.read_bytes()).hexdigest() for p in sorted((root / "inbox").glob("*.md"))} expected = json.loads((root / "state/source-baseline.json").read_text())["files"] assert actual == expected, "fixture baseline mismatch" print("PASS: source baseline matches") PY`

运行输出 **PASS** 代表环境合格，若报错说明素材缺失或被改动，需要重新同步官方原始文件。

**二、Gate 状态机测试｜核心省钱&增量触发逻辑（必掌握）**：预检脚本是整套任务的开关与成本核心，存在三种标准可复现状态，我已完整固化测试流程。第一次初始化运行：`python3 "$HOME/.hermes/scripts/lesson18-change-gate.py"`，无 `gate-state.json` 状态文件，自动全量扫描文件生成哈希快照，返回 `wakeAgent: true`，唤醒大模型执行任务；紧接着二次无修改重复运行相同命令，文件哈希无变化，返回 `wakeAgent: false`，直接跳过 LLM 推理、零 Token 消耗，这是日常稳定保活、节约成本的关键；接着手动模拟数据源更新：`printf '\n- 状态补充：本条仅用于练习变化检测。\n' >> "$HOME/hermes-daily-research/inbox/source-b.md"`，再次运行脚本，精准识别单文件增量变更，重新返回 `wakeAgent: true` 触发任务。测试结束必须还原官方原始素材、重置状态避免后续验收出错：`cp examples/lesson-18/inbox/source-b.md "$HOME/hermes-daily-research/inbox/source-b.md" && rm -f "$HOME/hermes-daily-research/state/gate-state.json"`。这里有一个极高频隐性坑点：Gate 脚本会**先写入新状态、再放行 Agent 执行**，如果后续模型推理、文件写入、TG 推送任意环节失败，状态文件已经更新，下次定时任务会误判“无变化”静默跳过任务，标准修复方案为：删除状态文件、手动重跑任务、重建基线。

**三、TG 网关配置｜安全可复现推送链路**：Hermes 以网关统一接管第三方消息推送，Cron 任务不直接联网发消息，隔离性强、稳定性更高。执行配置命令：`hermes gateway setup`，选择 TG（Telegram）平台，仅在网关向导内录入机器人 Token，**严禁将密钥写入 Prompt、命令行、日志或截图**，严格分离密钥与业务代码。TG 机器人需开启消息收发权限、订阅对应机器人消息事件，私有服务器采用 WebSocket 长连接，无需公网 IP 和 Webhook 地址。配置完成后启动并校验网关在线状态：`hermes gateway start && hermes gateway status`，前台调试环境可使用 `hermes gateway run` 常驻运行。在需要接收日报的 TG 会话发送 `/set-home`，绑定默认交付会话统一推送出口，生产环境必须配置用户白名单，禁止对外开放访问，杜绝恶意触发与指令注入风险。典型故障固定排查逻辑：本地产物正常但 TG 无消息，**禁止重跑 AI 任务**以免重复扣费，只需排查网关状态、Token 有效性、会话权限、白名单配置。推送配置完成后执行 `hermes tools` 收紧权限，仅保留 file 文件工具组，关闭终端、浏览器、委托等所有无用工具，既降低安全风险，又精简工具 Schema、减少 Token 开销，注意权限修改仅对**新 Cron 会话**生效，存量任务需要重建更新权限。

**四、创建 Cron 定时任务｜生产级可复现调度配置**：先读取本地标准 Prompt，再创建每日 8 点自动运行的定时任务，完整可直接执行命令：`PROMPT="$(cat "$HOME/hermes-daily-research/task-prompt.txt")" && hermes cron create "0 8 * * *" "$PROMPT" --name "lesson18-daily-research" --deliver telegram --script "lesson18-change-gate.py" --workdir "$HOME/hermes-daily-research"`。核心关键参数说明：定时表达式跟随**调度器系统时区**，并非北京时间，需提前核对防止错时；绝对路径 workdir 强制隔离读写范围，避免文件污染与泄露；绑定预检脚本实现智能启停；交付固定指向 TG；任务会固化创建时刻的模型与服务商，全局模型更新不会静默替换，而是失败闭源，杜绝未知扣费。任务创建后执行 `hermes cron list && hermes cron status` 查看并记录真实 JobID，后续所有运维均使用真实 ID，不使用占位符。调试阶段执行单次受控试跑，保证环境纯净：`rm -f "$HOME/hermes-daily-research/state/gate-state.json"`，随后手动触发任务：`hermes cron run 你的真实JobID`。需要明确：`cron run` 是异步登记触发，命令返回成功不代表任务完成，**三层验收全部通过才算闭环**：本地生成 `daily-brief.md` 产物、`python3 "$HOME/hermes-daily-research/verify_artifact.py"`校验通过、目标 TG 会话成功收到日报，禁止多次重跑导致扣费与刷屏。

**五、运维止损｜故障修复｜安全清理（生产核心能力）**：日常运维核心可控指令：任务暂停止损 `hermes cron pause 真实JobID`、任务恢复`hermes cron resume 真实JobID`、永久删除任务`hermes cron remove 真实JobID`。Pause 是第一安全止损操作，只冻结未来定时触发，保留全部配置与状态，不中断正在运行的任务、不撤回已推送的 TG 消息，适合故障观察、预算管控、临时停机维护。整套工作流三类标准可复现故障：一是状态机超前故障，Agent 执行失败但状态已更新，下次静默跳过，解决方式为删状态文件+手动重跑；二是交付层故障，本地产物正常、TG 无推送，只排查网关与 TG 权限链路，不重跑推理任务；三是产物质量故障，推送成功但文件不合格，先暂停任务、修复 Prompt、重置状态后重试。通用排错顺序：核查 Cron 任务状态 → 手动单独运行预检脚本 → 校验目录读写权限 → 检查网关在线状态 → 核对 TG 权限、事件订阅与日志。费用管控可执行 `hermes insights --days 7` 查看七日消耗趋势，整套任务仅数据源变更时产生 LLM 费用，无变化零开销，每日仅一次有效调度，成本高度可控。永久下线完整无痕清理流程：暂停并删除 Cron 任务 → `hermes gateway stop` 停止网关 → TG 后台轮换/撤销机器人 Token → 执行 `hermes gateway setup` 清空 TG 配置 → 删除本地练习目录与脚本 → 再次校验 Cron 与网关无残留，切记本地删除文件无法替代服务端密钥注销，服务端销毁才是杜绝盗用、隐形扣费的关键。

整套实操落地后，我完整掌握了从环境搭建、状态机原理、TG 推送配置、定时调度、闭环验收、故障定位、成本管控到安全下线的全链路生产级能力，这套低开销、可止损、可审计、可运维的自动化工作流，可以直接平移应用到资讯巡检、知识库增量汇总、日常资料整理等真实业务场景，是 Hermes 自动化体系中最贴合生产、实用性最强的核心实战能力。

实操案例针对参会者 B 的飞书群运营智能助手需求：直接使用单一会话 session 会把代码、文案、运营等全部上下文混在同一个 profile，长期运行会发生上下文污染，输出质量下降，Hermes 的 boot 插件可以生成多个互相独立 profile，记忆、skills、so.md 全部隔离，对应到飞书就是创建多个飞书机器人，每个机器人绑定独立 profile，专门的运营机器人挂载知识库对外应答。知识库接入最简方案用 Obsidian MD 库，根目录配置 agent.md 定义知识库分类、使用规范，再在 profile 的 source.md 约束机器人必须基于知识库作答，禁止编造内容；复杂知识库场景不推荐传统 IG 切片方案，主流做法是开发 MCP 服务给 Bot 调用实现知识库访问；飞书文档、多维表格 token24 小时失效的痛点，不能直接把静态 token 交给 Agent，要使用飞书官方 CLI 标准库处理鉴权。TG 接入逻辑同理，需要多个 TG Bot 分别绑定不同 profile，TG 的 topic 只是前端分类，不改变底层 profile，单 Bot 下所有 topic 共享同一套记忆。关于 Agent 团队搭建，没有通用配置，需要对齐业务流程，例如软件研发场景，就要拆分需求处理 Agent、编码 Agent、CodeReview Agent、测试 Agent、运维上线 Agent，每个 Agent 承担对应岗位角色，协同完成流水线。
