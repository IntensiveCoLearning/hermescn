# 2026-08-27

Day 1：安装并完成第一次对话（环境验证与 doctor 诊断）

## 完成内容

1. **确认 Hermes Agent 运行环境**：当前 Hermes 运行在 macOS 宿主机上，终端后端为 Docker 容器（Debian 13 trixie, aarch64, Linux 6.12.76）。容器内提供 Python 3.11.15、Node v20.20.2 等基础工具链。

2. **环境验证**：通过实际工具调用验证了 Hermes 的核心能力——terminal 命令执行、文件读写（read_file/write_file）、网页搜索（web_search）、网页内容提取（web_extract）、浏览器驱动（browser_exec）、桌面操控（computer_use）、技能系统（skill_view/skills_list）等均已正常工作。

3. **理解 Hermes 架构**：Hermes Agent 是 Nous Research 开发的开源 AI Agent 框架，核心设计是"AI Agent 中间件"——连接 LLM 模型与系统工具。同一套 Agent 核心驱动 CLI、Desktop 桌面应用、Web Dashboard、Telegram/Discord/Slack 等多平台网关。

4. **首次对话实践**：通过 Desktop GUI 与 Hermes 完成首次对话，成功执行了环境探测命令，获取了真实的系统信息并回传。

## 学习收获

- **Profile 机制**：Hermes 支持多 Profile 隔离运行，每个 Profile 有独立的配置、会话、技能和记忆。当前运行在 `learnme` Profile 下。
- **Skills 系统**：技能（Skills）是 Hermes 的"程序性记忆"，可复用的流程被保存为 SKILL.md 文件，在未来会话中自动加载。当前已加载了 hermes-agent、computer-use 等数十个技能。
- **Memory 持久化**：跨会话记忆通过 memory 工具持久化保存，注入到每次对话的系统提示中，实现"记住用户偏好"的能力。
- **Docker 终端隔离**：终端后端运行在 Docker 容器中，与宿主机隔离，安全性更好但需要注意路径差异。

## 遇到的问题

- **hermes CLI 不在 Docker 容器内**：由于终端后端是 Docker，`hermes doctor` 等 CLI 命令无法在容器内直接执行，需要通过其他方式获取宿主机上的诊断信息。
- **API 更新需要 updatedAt 字段**：尝试通过 PATCH 接口更新打卡内容时，发现必须传入 `updatedAt` 字段才能通过校验，初次尝试时报了 validation_error。

# 2026-08-28

Day 2：熟悉 Hermes 的基础使用

## 完成内容

1. **Skill 技能系统实战**：今天深入体验了 Hermes 的 Skills 系统。通过 skills_list 查看了可用技能列表，又用 skill_view 加载了 hermes-agent、computer-use、obsidian 等多个技能的完整内容。发现 Skills 本质是结构化的 Markdown 文件，包含触发条件、执行步骤、常见陷阱等板块，相当于给 AI Agent 装上了「可复用的操作手册」。

2. **skill_manage 创建技能**：动手用 skill_manage(action=create) 创建了一个自定义技能，体验了从构思到发布的完整流程。技能系统支持 SKILL.md 主文件加 references/templates/scripts 子目录的结构，设计得很实用。

3. **delegate_task 子任务委派**：用 delegate_task 派出了两个并行子任务，验证了子 Agent 的隔离性和结果回传机制。每个子 Agent 拥有独立的终端会话和工具集，最终只返回汇总结果。这对拆分复杂任务很有价值。

4. **cron 定时任务体验**：了解了 Hermes 的 cronjob 系统——可以设定时触发的 Agent 任务，适合自动巡检、定时报告等场景。今天这个打卡本身就是通过 cronjob 执行的，亲身感受到了自动化调度的能力。

5. **memory 持久化记忆**：用 memory 工具保存了用户偏好等信息，验证了跨会话记忆的读写机制。记忆会注入到每次对话的系统提示中，实现了「不用重复说」的体验。

## 学习收获

- **Skills 是 Hermes 最强大的扩展机制**：不同于简单的提示词模板，Skills 包含了工具调用的具体命令、错误处理策略和验证步骤，质量远高于自然语言指令。好的 Skill 能显著降低 AI 的犯错率。
- **子任务委派 = 分治思想**：delegate_task 让复杂任务可以拆分成独立的子工作流并行执行，每个子 Agent 有自己的上下文窗口，不会互相干扰。这和软件工程中的「单一职责」原则异曲同工。
- **Browser Use 的两种模式**：browser_exec 用于通用网页操作，computer_use 用于桌面应用控制。前者更适合数据抓取和表单填写，后者能操控任何 macOS 应用，各有适用场景。

## 遇到的问题

- **delegate_task 子 Agent 无法交互**：子 Agent 是「叶节点」，不能调用澄清、发送消息等工具，所以遇到模糊需求时只能自行推断。设计上需要把所有上下文在 goal/context 参数中交代清楚。
- **Skills 的命名规范需要留意**：创建技能时名称只能用小写字母、连字符和下划线，最多 64 字符，和文件系统约定类似但有细节差异。
