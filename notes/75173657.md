# 2026-08-27

Day 1：安装并完成第一次对话（环境验证与 doctor 诊断）

## 完成内容

1. **确认 Hermes Agent 运行环境**：当前 Hermes 运行在 macOS 宿主机上，终端后端为 Docker 容器（Debian 13 trixie, aarch64, Linux 6.12.76）。容器内提供 Python 3.11.15、Node v20.20.2 等基础工具链。

2. **环境验证**：通过实际工具调用验证了 Hermes 的核心能力——terminal 命令执行、文件读写（read_file/write_file）、网页搜索（web_search）、网页内容提取（web_extract）、浏览器驱动（browser_exec）、桌面操控（computer_use）、技能系统（skill_view/skills_list）等均已正常工作。

3. **理解 Hermes 架构**：Hermes Agent 是 Nous Research 开发的开源 AI Agent 框架，核心设计是"AI Agent 中间件"——连接 LLM 模型与系统工具。同一套 Agent 核心驱动 CLI、Desktop 桌面应用、Web Dashboard、Telegram/Discord/Slack 等多平台网关。

4. **首次对话实践**：通过 Desktop GUI 与 Hermes 完成首次对话，成功执行了环境探测命令，获取了真实的系统信息并回传。

## 学习收获

- **Profile 机制**：Hermes 支持多 Profile 隔离运行，每个 Profile 有独立的配置、会话、技能和记忆。当前运行在 `learnme` Profile 下。
- **Skills 系统**：技能（Skills）是 Hermes 的"程序性记忆"，可复用的流程被保存为 SKILL.md 文件，在未来会话中自动加载。当前已加载了 hermes-agent、computer-use 等数十个技能。
- **Memory 持久化**：跨会话记忆通过 memory 工具持久化保存，注入到每次对话的系统提示中，实现"记住用户偏好"的能力。
- **Docker 终端隔离**：终端后端运行在 Docker 容器中，与宿主机隔离，安全性更好但需要注意路径差异。

## 遇到的问题

- **hermes CLI 不在 Docker 容器内**：由于终端后端是 Docker，`hermes doctor` 等 CLI 命令无法在容器内直接执行，需要通过其他方式获取宿主机上的诊断信息。
- **API 更新需要 updatedAt 字段**：尝试通过 PATCH 接口更新打卡内容时，发现必须传入 `updatedAt` 字段才能通过校验，初次尝试时报了 validation_error。
