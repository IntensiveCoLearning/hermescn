# 2026-08-27

# Hermes 残酷共学｜如何选择最适合自己的 Hermes 打开方式

Hermes 安装只需要一行命令，但是对于 Hermes 来说，使用的方式有 N 种 ，可以通过最适合自己的方式来使用 Hermes。

就拿我实际在用的环境举例。现在用来 Hermes 共学的这个跑在云服务器上，通过网关接进 Telegram 群聊。同一台服务器上，我也可以开终端用 TUI 跟它对话，出门在外可以通过手机上的 Telegram 找它。

另外我在自己的 Mac 上页安装了 Hermes，这个 Hermes 主要用来做开发，因为  Mac 上开发移动端和桌面端程序更加方便，梳理完成开发的需求和工作之后，可以使用  /goal 来触发 Hermes 进行 E2E 测试，自己将所有的功能调试完成，期间不需要人为干扰。

在开始使用 Hermes 之前，有一些基础的概念需要理解。

## Hermes 中 Session、Project、Profile 各是什么

Session 是一次对话。不管从哪个入口发起的，CLI、Telegram、Discord 还是定时任务，每次对话都是一条 session，记在 `state.db` 里。会话可以恢复、重命名、搜索、按平台过滤，也可以使用 `hermes --resume` 恢复 session。

Project 是一个工作目录。你在哪个目录里启动 Hermes，它就按哪个项目干活，自动加载项目根目录里的 AGENTS.md 或 HERMES.md，里面写的是这个项目的结构和约定。

Profile 是一整套独立的 Hermes 配置。一个 profile 拥有自己完整的配置、密钥、记忆、技能、会话和定时任务，相当于同一台机器上启动了多个 Hermes。最近 Hermes 推出的 Bot Mode 本质上就是让每个 Bot 拥有一个独立的 Profile。这个也是后续 Agent 使用的趋势。


## Hermes 的打开方式

Hermes 支持多种打开方式。

最简单的方式是直接在命令行打开，但这种方式目前已经不推荐是使用了。
```shell
hermes
```

![Pasted image 20260826221852.png](https://raw.githubusercontent.com/rayjun/hermescn-assets/main/Pasted%20image%2020260826221852.png)


如果想在命令行使用，可以使用 tui 使用，官方现在推荐用 TUI 跑交互式对话，它比老的命令行模式更好用。
```shell
hermes --tui
```

![Pasted image 20260826222039.png](https://raw.githubusercontent.com/rayjun/hermescn-assets/main/Pasted%20image%2020260826222039.png)


对于很多没有技术背景的同学，可以直接从 https://hermes-agent.nousresearch.com/desktop 下载桌面端程序。或者通过终端进行安装，然后就有了一个桌面端的 Hermes，这种方式比较适合没有技术背景的同学使用
```shell
hermes desktop
```

![Pasted image 20260826222748.png](https://raw.githubusercontent.com/rayjun/hermescn-assets/main/Pasted%20image%2020260826222748.png)


除了上面几种方式，Hermes 最灵活的方式就是通过网关进行配置，可以把 Hermes 接入到主流的聊天工具中，然后用户可以通过聊天工具来使用 Hermes。基本上支持了当前主流的聊天工具。

![Clipboard_Screenshot_1787754757.png](https://raw.githubusercontent.com/rayjun/hermescn-assets/main/Clipboard_Screenshot_1787754757.png)


当前比较受欢迎的是 Telegram + Hermes 组合。可以参考 Bruce 的 Telegram + Hermes 的配置方式：https://x.com/brucexu_eth/status/2091455215367250367


另外移动端的 Hermes 官方说已经在开发中了，但是估计还需要时间才能发布。

## Hermes 怎么使用 LLM 服务

Hermes 本身只是一个 Agent，本身不提供 LLM 服务，但是官方提供了 Nous Portal 中转站，可以直接连接到 Hermes 上。

除了 Nous Portal，Hermes 几乎支持当前主流的 LLM 服务。这些服务统称 provider，OpenRouter、Anthropic、OpenAI、Google Gemini、DeepSeek、xAI、Kimi、通义千问这些主流厂商都在列，国内和海外的 API 服务基本全覆盖。

![Pasted image 20260826224346.png](https://raw.githubusercontent.com/rayjun/hermescn-assets/main/Pasted%20image%2020260826224346.png)


换模型的入口有两个。装好之后想定默认模型，跑 `hermes model`，交互式选择 provider 和模型。对话中途想换，在 TUI 或聊天软件里发 `/model`，部分界面支持直接写 `provider:模型名` 的格式，连菜单都不用翻。每个会话的模型选择是独立的，互不干扰。

本地模型也能接。电脑上跑着 Ollama 或者 vLLM 这类服务，它们都提供 OpenAI 兼容的接口，在配置里填本地地址和端口就行。好处是数据不出机器，坏处是本地模型对机器要求高。

## 通过 Tailscale 来组织一个 Hermes 网络

因为跨机器的两个 Hermes 互不相通，会话不会自动同步。机器多了以后，就很难管理。每台服务器都有自己的地址，有的在内网，有的在云上，端口还得一个一个转发，管理起来很烦。

我的做法是用 Tailscale 把所有机器串成一个私有网络。Tailscale 是一个组网工具，在每台设备上装好并登录同一个账号，这些设备就自动组成一个互通的虚拟内网，每台拿到一个固定的 100.x 开头的内网 IP。手机、笔记本、云服务器、家里的机器，互相都能直达，不用公网 IP，不用端口转发，也不用暴露到公网。

Tailscale 管理的是网络，不是 Hermes 本身。Hermes 该配的认证、白名单、密钥这些还是都需要配置，组网只是让你不用把这些东西暴露到公网上。

## 怎么选

在不同的场景可以用不同的方式。个人电脑上，日常对话和写东西用桌面应用或者 TUI，图形界面的用桌面，远程 SSH 就用 TUI。

但是对于最合适的方式，还是需要打开网关，然后通过聊天工具（比如 tg）+ Hemrs 的方式来使用。这种方式也是最符合未来 Agent 的形式的，Agent 需要随时响应，不能每次使用的时候，都打开电脑。

目前基本上每个人都离不开手机，所以通过手机来触发也是最合理的方式，我目前也在做一个移动端，希望能解决在移动端上的使用。

# Hermes 残酷共学｜日常配置和常用技巧，让 Hermes 自己做更多的事情

在安装完 Hermes 之后，就可以用起来了，虽然在大多数时候，直接把自己的需求整理成文字然后发给 Hermes 就可以，然后让 Hermes 来完成剩下的工作。

但是这样用起来 Hermes 几乎就是一个黑盒，你不知道它内部到底是怎么执行的，所以需要掌握一些基础的命令和配置，让 Hermes 在运行的过程，能够暴露出一些信息，让我们更容易观察到 Hermes 的状态，以及控制它的执行行为。

## Hermes 常用命令

Hermes 内置了很多的命令，这些命令可以用来执行对 Hermes 的行为进行控制，或者更改 Hermes 的配置。

无论是使用 tui、桌面端或者 tg 使用 Hermes，所有触发的方式都是一样的，使用斜杠触发。

tui 中触发。

![Pasted image 20260828080746.png](https://raw.githubusercontent.com/rayjun/hermescn-assets/main/Pasted%20image%2020260828080746.png)

tg 中触发。

![Pasted image 20260828080821.png](https://raw.githubusercontent.com/rayjun/hermescn-assets/main/Pasted%20image%2020260828080821.png)

Hermes 桌面端中触发。

![Pasted image 20260828080839.png](https://raw.githubusercontent.com/rayjun/hermescn-assets/main/Pasted%20image%2020260828080839.png)


Hermes 中内置的这些命令是一段内置程序，不是 skills。每条命令在 Hermes 的命令注册表里都有定义，包含命令名、说明、参数格式和所属分类，背后是写好的处理逻辑。比如 `/new`，执行的是开新会话那段程序，`/model` 用来更换大模型。这些命令的行为和入口无关，TUI、桌面端、Telegram 里表现一致。

skills 存在 `~/.hermes/skills/` 目录里，内容是完成某类任务的步骤、命令和注意事项，agent 干活前先读它照着做。技能安装之后也会生成斜杠命令入口，比如用 `/learn` 学会的技能，之后发 `/技能名` 就能直接触发。从本质讲，命令是程序，技能是说明书。命令表之外，config.yaml 里还能自定义 `quick_commands` 快捷命令，把常用话术绑到斜杠上。

Hermes 内置的命令很多，还可以安装更多的 skills，但是对于大多数命令，都不需要死记硬背，因为几乎所有的这些命令和 skills，我们都可以使用自然语言来触发。

在日常使用中，更合适的习惯是使用自然语言来触发，这个更适合未来 Agent 的打开方式。所以对这些命令有一个

### 常用命令

`/new` 开新会话 session。

`/title 名字` 给当前 session起标题，方便以后找回。

`/compress` 手动压缩上下文，长对话越聊越慢的时候用它，把前面压缩成摘要，腾出空间继续聊。

模型相关的还有 `/model` 切换模型、`/reasoning` 调整思考强度。写复杂代码把思考强度调高一档，简单问答调低，思考的复杂度越高，那么响应的速度就会越慢。

单轮问答之外，Hermes 还有一套目标机制，适合跨多轮才能完成的事。发一条

```bash
/goal 把仓库里 review 标注的问题全部修完，每个问题都要有验证
```

想中途加条件，就是用 `/subgoal`。当前任务跑了一半，你想补一条条件，直接

```bash
/subgoal 顺带把 README 也更新了
```

在当前 session 中，可以让 Hermes 派出独立子代理。子代理有自己独立的上下文，跟当前这个互不干扰，可以并行干活和独立检查。

让另一个它来审查刚做完的工作，用 `/review`。

```bash
/review 检查这个 PR 的改动有没有安全问题，逻辑漏洞，以及测试覆盖
```

想看看现在有几个子代理在跑、后台任务进展如何，用 `/agents`（别名 `/tasks`）。派出去的审查子代理、正在跑的后台任务，都能从这里看到状态。

没有单独的 `/subagent` 命令。日常用法就两种，审查工作用 `/review`，看子代理和后台任务的状态用 `/agents`。想并行处理多个独立任务，直接跟它说"派个子代理去查这个、再派一个去查那个"，它自己会用工具调度。

另外 Hermes 中有一个越用越好用的机制。Hermes 会把重复要做的事保存成 skills，后续使用一句话就能触发。

比如一个写作流程，可以用 skills 检查文本有没有违规词、调整文章风格、检测专属的写作禁忌，每一条都是一个 skills。可以将多个 skills 组合成自己的工作流。

在 Hermes 把工作经验变成技能有三种方式，分别是 `/learn`、`/refine` 和直接在对话里让 agent 用 `skill_manage`。

`/learn` 是显式的技能学习命令。后面可以加上具体的信息来源，比如书籍、网址、还可以是"刚才这段对话"都可以，它会把这些材料整理成一份符合规范的 skills 并存进目录，之后用 `/skills 麦城` 触发。

`/refine` 是隐式的经验整理。它把当前整段对话过一遍，值得记住的判断和偏好写进记忆，能复用的流程存成技能。

还有一种就是直接在对话里说"把上面的流程流程存成技能"，agent 调 `skill_manage` 完成。

所有 Hermes 有一种活人感，很多时候，教过一次的事，不用第二次教，这是 Hermes 和普通聊天工具差别最大的地方，自己很多做事的方式和经验都会在 Hermes 沉淀，而且所有的这些数据都还是由自己控制的。

## 元 skills hermes-agent

Hermes 自带一个特殊技能，叫 hermes-agent，一般来说会隐式触发，也可以使用斜杠来触发。这个技能的内容是 Hermes 自己的说明书，命令行参考、全部斜杠命令、配置文件路径、常见故障排查、开发贡献规则都在里面。

![Pasted image 20260828145042.png](https://raw.githubusercontent.com/rayjun/hermescn-assets/main/Pasted%20image%2020260828145042.png)

它的用途是让 agent 在配置、扩展或调试 Hermes 自身时有明确的规则。我让它改配置、查命令、排查网关问题的时候，它会先加载这个元技能，按里面的官方命令清单和排障步骤干活，而不是凭训练记忆瞎试。想改哪项配置、有哪些斜杠命令、日志在哪里，这个技能里都有答案。

在对话里临时加载用 `/skill hermes-agent`，装好之后它会在 agent 准备处理 Hermes 相关任务时自动出现。这算元技能的典型用法，用一套关于工具自己的知识，让工具正确地操作自己。

这个 skills 可以说是 Hermes 中最要的一个 skills，可以认为是所有 skills 的元 skills。

## md 文件的配置

在 Hermes 中，需要自己配置一些关键的 md 文件，Hermes 可能会根据这些不同的 md 文件做出不同的气质的行为。

在配置的时候需要重点关注：

- SOUL.md：这个文件直接决定了你的 Hermes 的人格、语气、风格，会对你的产出产生很大的影响。在安装完 Hermes 之后有一个默认的文件，如果自己没有特别的需求可以不改动。每个 Hermes 的 Profile 有一个这个文件。
- AGENTS.md、hermes.md、CLAUDE.md：这些都是具体的项目规则，可以根据不同的项目进行编写，Hermes 在执行任务的时候会重点参考这些 md 文件中的规则。

另外 MEMORY.md、USER.md 都会由 Hermes 在运行的过程中自动更新，会记录工作过程中产生的偏好、约定和经验。

## 定时任务

Hermes 的定时任务是另外一个很重要的功能，可以用来完成一些周期性的任务，而且在定时任务中，可以直接调用 skill 来完成一些特定的工作和任务。而且可以单独为定时任务设置大模型，比如一些简单的定时任务就可以使用便宜的 LLM，这样更省 token。

我现在机器上挂了十几个定时任务，都是这么来的。DeFi 晨报周四周五早上九点推送，地址监控每十二小时查一次链上资产变动，AI 新闻素材每天早上八点整理好素材发到 Telegram。醒来直接过一遍就可以了，不用花很多时间去浏览信息。

## 为不同的场景设置不同的 LLM

除了可以在定时任务中设置不同的 LLM 之外，还可以为更多的场景来设置不同的 LLM，比如在视觉、上下文压缩、MCP 等场景，都可以设置不同的 LLM。

这个功能叫 Auxiliary Model，这个同样不用担心配置，可以直接交给 Hermes 自己来配置。

## 让 Hermes 自己做更多

在大多数情况，这些配置和命令其实都可以忘记，在使用 Hermes 的时候，要邀请更多使用自然语言来触发。尽早把 Hermes 培养成一个真正的 Agent 助手，而不仅仅是一个工具。这种真正的 Agent 助手，才是未来 Agent 能大规模使用的形态。

因为我认为在 AI 越来越普及的时候，我们更需要让自己使用的 AI 更加可控，而不是直接使用别人提供的黑盒，比如 Grok Bot，虽然在体验上确实不错，但是自己完全失去了对 Agent 的控制，自己用的越多，那么自己交出去的数据就越多。而且在长期使用 Agent 的过程中，我们还会通过 Agent 把自己的经验和性格都蒸馏出来，这些数据最好还是能被自己掌握。

基于这个原因，也是我认为最好使用开源可控的 Agent 的原因，目前来看，Hermes 可能是最适合的那个。
