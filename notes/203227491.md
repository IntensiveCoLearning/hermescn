# 2026-08-28

# Day 2 学习心得：熟悉 Hermes 基础使用

今天完成了 Hermes 7 日学习计划的第二天任务：熟悉 Hermes 的基础命令、工具系统、会话管理和 Gateway 的作用。

我先启动了 Hermes CLI，并确认当前模型是 `claude-sonnet-4-6`。通过 `/status`，我学会了查看当前会话 ID、路径、标题、模型、Token 使用量和 Agent 是否正在运行。看到底部状态栏里的 `17.6K/1M` 和 `2%` 后，我理解了上下文容量的概念：当前对话还很轻，不需要担心上下文太长。

今天重点练习了几个常用命令：

* `/help`：不知道有哪些命令时使用
* `/status`：查看当前模型、会话和运行状态
* `/model`：查看或切换 provider 和模型
* `/tools`：查看 Hermes 当前可用工具
* `/title`：给当前会话命名，方便以后找回

我还学会了区分命令、工具、Skill、Session 和 Gateway。命令是我直接输入的控制按钮；工具是 Hermes 自己调用的能力，比如读文件、运行命令、看网页；Skill 是可复用的任务说明书，告诉 Hermes 做某类任务时按什么流程来；Session 是一次聊天记录，关闭 CLI 后也可以找回；Gateway 是把 Hermes 接到微信等平台的桥，如果想在手机微信里聊天，就需要让 gateway 保持运行。

今天还有一个重要经验：虽然我只想让 Hermes 在聊天里输出内容，但它曾经主动创建了一个小抄文件。这提醒我，以后给 Hermes 下任务时要明确写清楚“不要修改任何文件”或“只在聊天中输出”。这也是以后安全使用 Hermes 的一个好习惯。

## 今日成果

* 成功启动 Hermes CLI
* 学会使用 `/help`、`/status`、`/model`、`/tools`、`/title`
* 理解了上下文状态栏的含义
* 确认当前模型 `claude-sonnet-4-6` 可以正常使用
* 理解了 Tool、Skill、Session、Gateway 的区别
* 学会了通过 `/title` 给会话命名
* 建立了“先说清是否允许改文件”的使用习惯

## 今日复盘

今天我发现 Hermes 不只是一个聊天窗口，而是一个带有工具、会话、模型配置和扩展能力的智能终端。真正高效使用 Hermes，不是记住所有命令，而是知道遇到问题时该看哪里：找命令用 `/help`，查状态用 `/status`，换模型用 `/model`，看能力用 `/tools`，整理会话用 `/title`。
