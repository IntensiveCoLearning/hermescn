# Day 2 学习心得：熟悉 Hermes 基础使用

今天完成了 Hermes 7 日学习计划的第二天任务：熟悉 Hermes 的基础命令、工具系统、会话管理和 Gateway 的作用。

我先启动了 Hermes CLI，并确认当前模型是 `claude-sonnet-4-6`。通过 `/status`，我学会了查看当前会话 ID、路径、标题、模型、Token 使用量和 Agent 是否正在运行。看到底部状态栏里的 `17.6K/1M` 和 `2%` 后，我理解了上下文容量的概念：当前对话还很轻，不需要担心上下文太长。

今天重点练习了几个常用命令：

* `/help`：不知道有哪些命令时使用
* `/status`：查看当前模型、会话和运行状态
* `/model`：查看或切换 provider 和模型
* `/tools`：查看 Hermes 当前可用工具
* `/title`：给当前会话命名，方便以后找回

我还学会了区分命令、工具、Skill、Session 和 Gateway。命令是我直接输入的控制按钮；工具是 Hermes 自己调用的能力，比如读文件、运行命令、看网页；Skill 是可复用的任务说明书，告诉 Hermes 做某类任务时按什么流程来；Session 是一次聊天记录，关闭 CLI 后也可以找回；Gateway 是把 Hermes 接到微信等平台的桥，如果想在手机微信里聊天，就需要让 gateway 保持运行。

今天还有一个重要经验：虽然我只想让 Hermes 在聊天里输出内容，但它曾经主动创建了一个小抄文件。这提醒我，以后给 Hermes 下任务时要明确写清楚“不要修改任何文件”或“只在聊天中输出”。这也是以后安全使用 Hermes 的一个好习惯。

## 今日成果

* 成功启动 Hermes CLI
* 学会使用 `/help`、`/status`、`/model`、`/tools`、`/title`
* 理解了上下文状态栏的含义
* 确认当前模型 `claude-sonnet-4-6` 可以正常使用
* 理解了 Tool、Skill、Session、Gateway 的区别
* 学会了通过 `/title` 给会话命名
* 建立了“先说清是否允许改文件”的使用习惯

## 今日复盘

今天我发现 Hermes 不只是一个聊天窗口，而是一个带有工具、会话、模型配置和扩展能力的智能终端。真正高效使用 Hermes，不是记住所有命令，而是知道遇到问题时该看哪里：找命令用 `/help`，查状态用 `/status`，换模型用 `/model`，看能力用 `/tools`，整理会话用 `/title`。

# Day 3 学习心得：把模糊需求变成可执行任务

今天完成了 Hermes 7 日学习计划的第三天任务：学习如何把一个模糊想法，逐步整理成 Hermes 能理解、能执行、能验收的任务提示词。

今天一开始，我没有直接让 Hermes 写代码，而是先给它一个模糊需求：“想做一个简单有趣的 Web3 小产品 demo，用来作为结营项目。”Hermes 先帮我分析这个需求中不清楚的地方，比如 Web3 的具体方向、项目难度、趣味性的标准、是否连接钱包、是否写智能合约、展示方式和验收标准等。

通过这一步我意识到，很多时候不是 Agent 不会做，而是我给的任务还不够清楚。如果我只说“帮我做个 Web3 demo”，Hermes 可能会自行发挥，加入我并不想要的复杂功能，比如真实钱包连接、链上交互或智能合约。对新手来说，这会让项目变复杂，也可能带来安全风险。

之后，我根据这些模糊点主动补充约束，把项目收窄为一个本地静态网页：Wallet Quest Card。它只使用 HTML、CSS 和 JavaScript，展示模拟钱包身份卡、任务进度、成就徽章和安全提示。不连接真实钱包、不签名、不上链、不保存私钥，也不调用真实 Web3 API。这样项目既保留了 Web3 的趣味感，又适合在短时间内完成。

今天最重要的收获是学会了一个控 Agent 的流程：

模糊需求 → 问题分析 → 约束收敛 → 可执行任务卡 → 正式提示词

这个流程不是某个固定命令，而是从 HermesCN 教程中“目标是什么、输入在哪里、允许做什么、怎样算完成”这些原则延伸出来的实践方法。它让我明白，使用 Hermes 时不能只把需求扔给它，而要先和它一起把任务边界讲清楚。

我还学会了在提示词里加入执行权限控制，比如：

第一阶段只分析和给计划，不创建或修改文件；\
只有我回复“确认执行”后，才能创建或修改文件。

这句话很关键，它能避免 Agent 在需求还没确认时就直接写文件，也让整个协作过程更安全、更可控。

今日成果：

* 学会让 Hermes 先分析模糊需求，而不是直接执行
* 明确了 Web3 Demo 的方向：Wallet Quest Card
* 生成了一张完整任务卡
* 生成了 Day 6 可直接使用的正式执行提示词
* 理解了任务卡中的关键字段：目标、范围、不做什么、文件边界、验收标准、风险提醒
* 学会了用“确认执行”控制 Hermes 的修改权限

今日复盘：

今天最大的变化是，我开始从“让 Agent 帮我做事”转向“我来控制 Agent 怎么做事”。一个好的任务提示词，不只是描述想要什么，还要说明不做什么、允许改哪里、怎样算完成。

以后给 Hermes 下任务时，我会优先使用这个公式：

目标 + 范围 + 不做什么 + 文件边界 + 验收标准 + 执行权限

# Day 4 学习心得：管理会话与修正结果

今天完成了 Hermes 7 日学习计划的第四天任务：学习 Session、Profile、Workspace 的区别，并练习如何管理会话和修正 Hermes 的回答。

今天我先通过 `hermes sessions list --limit 10` 查看了最近的 Hermes 会话，发现之前的学习记录和 Web3 项目需求分析都还在。这让我理解到，关闭 CLI 窗口并不代表对话丢失，Hermes 会把 Session 保存下来，以后可以通过会话列表找回。

接着我学习了 Profile 的概念。当前使用的是 `default` profile，模型是 `claude-sonnet-4-6`，Gateway 状态是停止，已安装技能有 93 个。Profile 可以理解成 Hermes 的一套配置环境，包含模型、API、技能、记忆等设置。它不是项目目录，也不是文件沙盒。

今天最容易混淆的是 Workspace。我一开始以为它可能是会话分组，但后来修正为：Workspace 是 Hermes 实际工作的文件夹，也就是它默认读写文件、运行命令的位置。比如我在 `PS C:\Users\*****>` 下运行 `hermes`，当前 Workspace 就是 `PS C:\Users\*****>`。这也解释了为什么之前的小抄文件会被创建在用户目录下。

今天还练习了一个非常重要的能力：修正 Hermes 的回答。当 Hermes 把 Workspace 解释成“Session 分组标签”时，我没有重新开始，而是指出错误事实，让它基于新的事实重新回答。这个过程让我理解到，使用 Agent 时不只是接受它的输出，也要学会纠偏。

今日成果：

* 会查看历史 Session
* 知道如何给当前会话设置标题
* 理解 Session 是一次聊天记录
* 理解 Profile 是一套配置环境
* 理解 Workspace 是工作目录
* 知道当前 Workspace 来自启动 Hermes 时所在的 PowerShell 路径
* 知道 Gateway 停止时，微信 bot 不会回复
* 学会用明确事实修正 Hermes 的错误回答

今日复盘：

今天我最大的收获是分清了 Hermes 的三个层级：Session 是“聊了什么”，Profile 是“用什么配置聊”，Workspace 是“在哪个文件夹干活”。以后每次使用 Hermes 做项目，我都会先确认当前目录，再启动 Hermes，并用 `/status` 检查路径是否正确。

我也记住了一个排错和修正模板：

你刚才有一点不准确：**。\
正确事实是：**。\
请基于这个事实重新回答。

这个模板以后可以用来修正概念解释、代码方案、项目计划和总结内容。
