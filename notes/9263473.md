# 2026-08-28

# Day 2｜熟悉 Hermes 的基础使用

今天按 HermesCN 官方教程「03 · 使用 Hermes 完成第一个可验证任务」完成了一次真实文件任务：不是继续聊天，而是让 Agent 读取明确输入、生成文件，并由我独立验收。

## 今天完成了什么

1. 在独立练习目录 `hermes-first-task` 中准备了官方提供的 3 份虚构材料：
   * `event-notes.txt`
   * `learner-feedback.txt`
   * `next-actions.txt`
2. 从该目录启动 Hermes，明确指定：只读这 3 个文件，只创建 `summary.md`，不修改原文件、不访问目录外文件、不调用网页或网络工具。
3. 在任务说明里写清了输入、目标、输出结构、边界、写入前确认点和验收要求。
4. Hermes 实际调用文件工具读取 3 份输入，先说明要创建 `summary.md`，再完成写入并回读检查。

## 一次很有价值的纠错

第一次结果并没有直接算通过。我逐条对照原文时发现：`next-actions.txt` 的“待认领：为 Desktop 工作目录步骤补充截图”没有截止时间，但 Hermes 在汇总表里写成了“下一次活动前”。这是原文不存在的信息。

我在同一会话中给出最小修正指令，只允许修改 `summary.md` 的这一格。Hermes 将其改为“原文未提供”，随后回读确认，没有重写其他章节。

## 四层验收结果

* **存在**：`summary.md` 已创建。
* **完整**：包含“活动目标、学员反馈（顺利 / 卡点 / 建议）、下一步行动、信息缺口”4 个部分。
* **准确**：反馈均注明来源文件；负责人和已有时间信息得到保留；缺失时间明确写成“原文未提供”。
* **未越界**：3 个输入文件的 SHA-256 与执行前完全一致；会话记录显示文件工具只读了 3 个输入，只写入/修正并回读了当前目录中的 `summary.md`，没有调用网页或网络工具。

最终目录中只有 4 个文件：3 个原始输入和 1 个新产物 `summary.md`。

## 今天的理解

1. 工作目录不是小细节，而是 Agent 的任务边界；第一次文件任务应与正式资料隔离。
2. “Agent 说完成了”不等于完成，必须自己检查文件、结构、事实和越界情况。
3. 最有价值的能力不是一次生成完美结果，而是发现具体偏差后，在同一会话里给出小范围修正。
