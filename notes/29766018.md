## 总结

<br />

核心观点：Agent 产出不满意，瓶颈往往不在模型，而在人没把任务讲清楚。解决办法不是把每句话写更长，而是用结构化框架固定上下文。

### 四层框架（从大到小）

| 层级                   | 载体                           | 解决什么     | 特点                            |
| :------------------- | :--------------------------- | :------- | :---------------------------- |
| 1. SOUL.md           | 身份性格文件                       | 风格与个人特质  | 一次配置长期生效，不用每次重复"用中文""别啰嗦"     |
| 2. Prompt 库 → Skills | 可复用技能                        | 通用流程标准化  | 好用的 prompt 存下来反复调用，从日常工作中逐步积累 |
| 3. AGENTS.md         | 项目规则文件                       | 领域/项目级约定 | 每个项目写一份，进目录自动读取，规矩固化不重讲       |
| 4. Hermes 执行机制       | `/goal` `/review` `/subgoal` | 执行中的质量兜底 | 前三层保证听懂任务，这一层保证做对事情           |

* `/goal`：把模糊目标变成带验收标准的契约
* `/review`：派独立子代理从零视角审查，查出顺思路漏掉的问题
* `/subgoal`：任务进行中不中断地补充条件

### 单次会话习惯

每条指令说清三件事：做什么 · 交付什么 · 怎么算完成。

> 反例："把几个问题修一下" 正例："看项目中标注待修的问题，按批注修复，改完发清单，每项写清改了什么、怎么验证"

### 一句话总结

不要把 Agent 当许愿池。 把模糊需求变清晰靠的不是完美 prompt，而是从固定的地方持续组织上下文——SOUL 定风格、Skills 定流程、AGENTS.md 定规矩、Hermes 机制兜底执行。养成习惯，交互就轻松了。

# 2026-08-30

## 今日学习笔记：Hermes Bot Mode — 从工具到协作

### 核心观点

当前主流 Agent（Codex、Claude Code 等）都还是 Session 模式，本质上是把 Agent 当工具用。Hermes 的 Bot Mode 把 Agent 从一次性会话中解放出来，赋予长期身份和角色，实现多 Agent 协作。

### Session vs Bot：本质区别

| 维度  | Session 模式            | Bot 模式                 |
| :-- | :-------------------- | :--------------------- |
| 定位  | 工具，随用随开               | 角色身份，长期存在              |
| 上下文 | 全挤在一个 profile 里，越用越膨胀 | 每个 bot 独立 profile，互不干扰 |
| 协作  | 单点执行                  | 多 bot 同群协作，围绕同一项目分工    |
| 持续性 | 做完即结束                 | 稳定存在，可融入固定工作流程         |

### Profile：Bot 隔离的基础设施

一个 Profile = 一套完整的独立 Hermes：配置、密钥、SOUL.md、记忆、Skills、定时任务、状态数据库，全部隔离。

典型分工举例：

* 编码 bot — 专注开发
* Review bot — 独立审查，能及时发现开发 bot 的方向偏差
* 监控 bot — 持续跟踪数据

多个 bot 拉入同一群聊 → 围绕同一项目协作，身份和记忆完全隔离，不会互相污染上下文。

### Bot vs Subagent：为什么 Bot 更好

Subagent 已经能拆分任务给干净上下文执行，但有个致命问题：一次性的，做完就消失，下次要重新创建。

Bot 的优势在于扩展性：

* 可按需创建任意新 bot
* Bot 本身稳定存在，融入长期工作流程
* Bot 内部仍可启动一次性 subagent 做具体执行，执行完 subagent 退出，bot 仍在
* 适合建立稳定的工作模式，而非每次从零开始

> 类比：Subagent 是临时工，Bot 是固定岗位。

### 当前局限

* Bot mode 暂时只能通过插件形式安装，仅限桌面端
* TG 中可通过创建多 Profile 实现类似效果
* 底层配置对普通用户还有一定门槛

### 未来展望

Bot 模式会成为多 Agent 协作的主流。对普通用户来说，最终只需启动多个 Agent bot、分配工作内容，底层 profile 配置完全屏蔽。

> 一句话总结：不要把 Agent 当工具用完即弃，给它固定身份和隔离环境，让多个 Agent 像团队一样长期协作——这才是 Agent 的正确打开方式。
